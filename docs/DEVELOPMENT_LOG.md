# Журнал разработки

Хронология по этапам. Записи описывают, что изменилось, почему так и как это проверялось.

## Этап 1 — играбельный прототип

Коммит `4ba90b5`.

Полный игровой цикл на `planck`: баллистика, попадания, разрушение конструкции по энергии удара, цепные реакции критических опор. Уровень `water_tower_01`. Процедурные рендер и звук, внешних ассетов нет. Сохранение настроек и рекордов. Headless-прогон как проверка баланса.

Проверка: `npm run verify` (48 тестов), `npm run playthrough` — победа, счёт 2666, ранг Perfect Demolition, 2 выстрела из 3.

## Этап 2 — меню, выбор уровня, переход в игру

Коммит не создан (работа в рабочем дереве).

Меню существовало, но `menu_start` сразу запускал первый уровень: выбрать было нечего, а прогресс игрока нигде не показывался. Добавлен экран выбора уровня.

### Состояния и ввод

- `GameState.LevelSelect` и переходы `MainMenu → LevelSelect → Playing`, `LevelSelect → MainMenu/Settings`, `Settings → LevelSelect`.
- Попутно исправлен отсутствовавший переход `Paused → Settings`: пункт «Настройки» в паузе не работал.
- `InputAction` `navigateUp`/`navigateDown` (`ArrowUp`/`KeyW`, `ArrowDown`/`KeyS`) для листания карточек.

### Экран выбора уровня

`LevelSelectController` в `src/ui/Controllers.ts`. Карточки строятся из реестра `LevelManager` плюс прогресс из `SaveManager`, поэтому добавление уровня не требует правок контроллера. Модель карточки — `LevelCard` (счёт, ранг, попытки, минимальное число выстрелов, замок). Навигация циклическая, Enter подтверждает, Esc возвращает в меню.

### Главное меню

Добавлена кнопка «ВЫБОР УРОВНЯ». `MenuModel` расширен полями `levelCount`, `completedLevelCount`, `canResume`; «ПРОДОЛЖИТЬ» подставляет `resumeLevelId()`.

Ранг в сохранении хранится строкой, поэтому `ScoringSystem.asRank()` проверяет его по известным значениям: неизвестная строка даёт «Нет результата», а не мусор в меню. `asRank()` вызывается и при сборке карточек уровня, а не только в меню.

### Дефекты, найденные при проверке этапа

Первая реализация проходила все проверки, но при чтении кода в ней нашлось шесть расхождений с поведением:

- Правая колонка карточки подписывала `maxShots` как «Запуски», а `minimumShots` — как «запуск(ов)», то есть показывала лимит выстрелов под именем числа попыток. При `minimumShots === null` строка «Попыток: 0» рисовалась дважды: в запасной ветке и в основной. Подписи переименованы в «Выстрелов» / «Мин. выстрелов» / «Попыток», каждая величина выводится ровно один раз.
- `canResume` вычислялся, но нигде не читался: кнопка всегда подписывалась «НАЧАТЬ РАБОТУ», хотя по этому флагу её смысл — «ПРОДОЛЖИТЬ». Теперь подпись зависит от флага.
- `resumeLevelId()` держал последний уровень только в памяти (`lastPlayedLevelId`). После перезагрузки страницы прогресс в сохранении оставался, а «ПРОДОЛЖИТЬ» открывала первый уровень. Добавлен второй шаг: если в памяти ничего нет, берётся уровень с самой свежей записью (`lastPlayedAt`) среди уровней с ненулевым числом попыток. В `LevelCard` добавлено поле `lastPlayedAt`.
- `LevelSelectController` копировал `drawBackdrop` из `MainMenuController` — две копии фона с разным шагом сетки. Фон вынесен в общую `drawMenuBackdrop`.
- Новый код вводил цвета вне `Palette` (`'rgba(30,37,44,0.95)'`, хардкод градиента `#0d1116`/`#1c232a`). Заменено на `Palette.graphite`/`graphiteLight` и `withAlpha(Palette.steel, …)`, как требует правило о палитре.
- `LevelSelectController.sync()` не вызывался ниоткуда — удалён как мёртвый код.

Правки не меняют баланс и не касаются физики: затронуты только меню, модель карточек и её отрисовка.

### Настройки

- `settings_reset` был нарисован, но не обрабатывался: клик по «Сбросить прогресс» ничего не делал.
- Чекбоксы не переключались: `UiCanvas.handlePointerUp` не менял `checked`. Теперь переключает, а `GameApp` сверяет контролы с сохранением и по клику, и по перетаскиванию ползунка.
- `fullscreen` больше не падает в headless-прогоне.

### Тестируемость

Чтобы меню можно было проверить без браузера, а не только «на глаз»:

- `GameApp.attach()` принимает минимальный интерфейс `GameCanvas` вместо `HTMLCanvasElement`; `asGameCanvas()` переводит DOM-canvas. Рендеру нужны только `getContext` и размеры.
- `GameApp.frame()` — один кадр целиком (ввод → логика → отрисовка → сброс кадрового ввода), `advance(frames, dt)` — прогон с фиксированным шагом. `requestAnimationFrame` и `window` теперь необязательны.
- `InputController.press(action)` имитирует действие без клавиатуры.
- Публичные `levelCards()`, `menuModel()`, `openLevelSelectForTest()` — точки наблюдения для тестов.

`tests/integration/menu-flow.test.ts` (16 тестов) на `@napi-rs/canvas`: загрузка в меню, переход в настройки и обратно, переход на экран уровней, по одной карточке на каждый уровень реестра, клик и клавиатурный выбор карточки, Esc назад, старт уровня, тик и отрисовка сцены, пауза/возобновление, рестарт, продолжение с последнего уровня, отображение рекорда, поведение при неизвестном ранге в меню и в карточке, доступность «Продолжить» по прогрессу из сохранения. Тест ищет кнопки по id контрола, а не по координатам, — раскладку можно менять без правок теста.

Две из этих проверок добавлены вместе с правками дефектов: неизвестный ранг в карточке (проверяет `asRank()` в `levelCards()`) и «Продолжить» по сохранению (проверяет вторую ветку `resumeLevelId()`).

Отдельно устранена плавающая падача тестов: ожидание старта уровня держалось на фиксированном числе витков `event loop` (`settle()` — 10 итераций). Этого хватало не всегда: загрузка JSON идёт через динамический `import`, и её длительность зависит от прогрева кэша модулей, из-за чего тест «клик по карточке запускает уровень» периодически падал с `level_select` вместо `playing`. Заменено на ожидание условия (`waitForPlaying`) с таймаутом. Восемь последовательных прогонов файла — без падений.

Проверка: `npm run verify` — 64 теста, format, lint, typecheck, build; `npm run playthrough` — победа, счёт 2666, ранг Perfect Demolition, 2 выстрела из 3, результат не изменился.

## Открытые вопросы

- Визуальная проверка в браузере не выполнялась: в среде нет ни `DISPLAY`, ни браузера. Проверка ограничена headless-тестами, отдающими кадр в `@napi-rs/canvas`. Перед релизом нужен ручной прогон главного меню.
- Зарегистрирован один уровень. Экран выбора рассчитан на любое число, но проверен на одном: с несколькими уровнями нужна прокрутка или страницы списка.
- `largeDebrisMass: 40` в уровне: красная зона выставляется по порогу крупных обломков, который заметно ниже фактической массы. Проверка входов и победы не затронута, но баланс зоны стоит пересмотреть в отдельном этапе.
- Меню и экран выбора уровня проверены только headless-тестами. Ручной прогон в браузере не выполнен, поэтому раскладку карточек и поведение курсора стоит посмотреть глазами до релиза.
