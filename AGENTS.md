# AGENTS.md

Рабочие инструкции для агентов и людей, ведущих репозиторий.

## Команды

```bash
npm run dev            # локальная разработка
npm run verify         # format:check + lint + typecheck + test + build
npm run test:unit
npm run test:integration
npm run playthrough    # headless-прогон уровня, код возврата != 0 при поражении
```

`npm run verify` должен проходить целиком перед коммитом. `npm run playthrough` обязателен после любой правки `src/levels/*.json`, `DestructionSystem` или `GameSession`.

## Архитектурные правила

- Игровая логика (`data`, `physics`, `gameplay`) не импортирует DOM, Canvas или WebAudio. Рендер и звук получают только снимки состояния.
- Стиль — только значения из `src/render/Palette.ts`. Внешние ассеты, шрифты и картинки не добавляются.
- Урон и разрушение считаются в `DestructionSystem` по энергии удара, а не по импульсу: падение сверху и удар снарядом должны давать сопоставимый результат.
- Элементы с `destructible: false` (генератор, земля) не переходят в `destroyed`, только накапливают урон.
- Цепные реакции (`criticalCollapse`) используют исходные координаты схемы, а не текущие координаты падающего элемента.
- Ввод читается один раз за кадр; состояния «в этом кадре» снимаются в `InputController.endFrame()`.

## Уровни

- Уровень — JSON в `src/levels/` плюс запись в `LEVELS`. Данные проходят `validateLevel` до создания физики.
- Эталонный план победы дублируется в `tools/headless-playthrough.ts` и `tests/integration/playthrough.test.ts`. Правка баланса без обновления обоих мест недопустима.

## Стиль кода

- Комментарии объясняют «почему», а не «что». Новый код пишется без комментариев, если намерение читается из имён.
- Импорты типов — через `import type` (правило `consistent-type-imports`, автофикс доступен через `npm run lint:fix`).
- Тесты и CLI-скрипты в `tools/` — единственные места, где допустим `console`.
- Форматирование — Prettier, линтер — ESLint flat config. Оба обязательны к коммиту.

## Тесты

- `tests/unit` — чистые функции и структуры данных, без физики.
- `tests/integration` — полный `GameSession` с реальной симуляцией; проверяет воспроизводимость покадрово.
- Симуляция детерминирована: одинаковый вход даёт одинаковые кадры, счёт и урон. Это используется в тестах, поэтому не вводить зависимость от `Math.random` или времени суток.
